# Kris 首页与导航 VNext

> 2026-09-06 更新：产品路线以 [日常健康与专业训练](PRODUCT_ROADMAP_2026-09-06.md) 为准。以下保留早期设计记录；首页不再强制准备度居首，Mac 配对不作为产品要求。

> 决策日期：2026-09-02
> 状态：产品结构已收敛，视觉方向待确认后实施
> 目标：从“训练日报 + 数据控制台”升级为本地优先的个人健康与训练操作系统。

## 1. 产品角色

首页不能只回答“今天练不练”，而要在 10 秒内回答三个问题：

1. 我今天的身体状态怎么样？
2. 哪些变化值得我注意？
3. 我现在最值得做的一件事是什么？

训练计划是首页行动的一部分，不是首页的全部。准备度、压力、恢复、睡眠、活动和身体组成都采用确定性算法与可追溯来源，不把估算包装成医学结论。

## 2. 一级导航

底部固定为五个一级入口：

| Tab | 用户问题 | 核心内容 |
|---|---|---|
| `今日` | 我现在怎么样、该做什么？ | 今日状态、关键变化、唯一主行动、进行中的训练、简短健康摘要 |
| `健康` | 我的各项身体数据具体怎样？ | 恢复、压力、睡眠、活动、身体组成、心肺能力与单项详情 |
| `训练` | 我练什么、怎么记录、练得怎样？ | 当前训练、计划库、用户编辑、训练历史、动作进阶 |
| `趋势` | 最近发生了什么、哪些因素有关？ | 7/28/42/90 日趋势、基线、关联视图、周/月总结 |
| `设置` | 我怎样管理权限、设备和偏好？ | 健康权限、Watch、同步、隐私、外观、辅助功能与诊断 |

固定顺序为 `今日 / 健康 / 训练 / 趋势 / 设置`。`数据`不再作为产品概念或一级入口；现有 DataView 的能力按用户任务拆入 `健康`与`设置`，不能只把页面改名。

普通页面右上角不再放全局设置按钮，顶部空间只保留当前页面相关操作。开始训练后进入专注执行界面，训练控制优先；该界面不混入设置入口，退出训练执行态后恢复五项底部导航。

## 3. 设置页面

设置只承载低频配置和故障恢复：

- Apple 健康：授权状态、数据类别、最近读取时间、重新授权说明。
- Apple Watch：安装、配对、可达状态、训练模式说明。
- 通知与实时活动：训练提醒、休息结束、锁屏与灵动岛。
- 数据源与新鲜度：来源优先级、采样时间、读取时间和覆盖质量。
- Mac 与归档：可选配对、离线队列、最后归档结果、故障重试。
- 外观与辅助功能：深浅色、触感、动态字体与减少动态效果。
- 隐私与数据：端侧处理说明、导出、删除、取消配对。
- 关于与诊断：版本、规则版本、匿名诊断导出和高级日志。

设置虽然是第五个正式底部入口，但不承担日常查看健康数据的任务；普通用户无需理解批次、游标、证书或队列实现。

## 4. 今日首页结构

### 首屏

1. 顶部：日期、简短问候和数据新鲜度状态；不重复放置全局设置按钮。
2. 今日状态：一个综合结论，展示准备度、当前压力/负荷状态和置信度；可以进入证据详情。
3. 关键变化：只显示相对个人基线最值得注意的 1–3 项，例如睡眠不足、HRV 偏低、静息心率升高或活动不足。
4. 今日行动：只保留一个主按钮。训练日进入计划或继续训练；非训练日显示恢复、步行或睡眠行动。

### 次屏

- 健康速览：恢复、睡眠、活动、身体组成四个领域的当前值与方向，点击进入健康详情。
- 今日活动：步数、活动能量、锻炼分钟和圆环式进度，但不把不完整日当作最终结果。
- 最近训练或计划：训练日显示计划摘要，训练后显示本次训练结果；不同时堆叠两张大卡。
- 数据缺口：只有会改变结论或需要用户处理时才出现，普通后台更新不占首页空间。

## 5. 健康页结构

健康页采用领域入口，不把所有指标平铺成仪表盘：

1. `恢复与压力`：准备度、HRV、静息心率、近期训练负荷、压力估算和证据置信度。
2. `睡眠`：总时长、阶段、规律性、睡眠负债与近 7 日趋势。
3. `活动`：步数、活动/静息能量、锻炼分钟和运动分布。
4. `身体组成`：体重、体脂、去脂体重、BMI 和晨起成套体测质量。
5. `心肺能力`：VO2 max、步行心率和有连续覆盖的训练心率指标。
6. `身心与环境背景`：Apple 健康中的心境、日照、呼吸频率和血氧等可用信号；默认低权重，不因稀疏记录改变训练处方。

所有详情统一显示：当前值、个人基线、变化方向、来源、更新时间、数据质量、算法影响和可交互曲线。

### 市场体验对齐范围

首轮健康体验至少覆盖恢复、非医疗压力估算、睡眠、活动、身体组成、心肺、训练记录、数据新鲜度和交互趋势。情绪/习惯记录、小组件和主题属于后续留存层，不能优先于启动速度、数据可信和 Watch 训练闭环。目标不是复制竞品页面数量，而是在状态可解释、力量训练闭环、离线可靠和数据来源透明四项上形成可验证优势。

## 6. 压力与恢复的算法边界

- `恢复`用于判断相对个人基线的训练准备状态。
- `压力`是基于 HRV、静息/当前心率、睡眠、活动与近期训练负荷的非医疗估算，必须显示置信度和缺失输入。
- 没有足够数据时显示“数据不足”，不得显示正常或低压力。
- 不声称 Apple Watch 提供了系统原生压力值；不把单次 HRV 或心率峰值解释为心理状态。
- 所有规则有版本、输入时间窗、证据和回退条件，AI 不参与实时分数计算。

## 7. 首屏性能方案

修改前，App 初始化阶段会同步创建 SwiftData 容器，并在主线程读取计划、训练历史、全部计划列表和五次队列统计；随后立即启动 HealthKit 观察、Bonjour 和前台刷新。这会让首屏工作集中，符合用户感知到的轻微卡顿。第一轮已把训练历史、队列统计、HealthKit 观察与 Bonjour 延迟到首帧之后；当前计划和正在进行的训练仍同步恢复。剩余优化需要真机性能基线和轻量日聚合快照支持。

改造为三阶段启动：

1. `First Frame`：只创建必要容器，立即显示上次保存的轻量 `DashboardSnapshot` 与当前计划摘要。
2. `Local Hydration`：首帧后异步恢复完整计划、最近 10 条训练和健康日聚合；历史按需分页，不在启动时解码全部计划。
3. `Background Refresh`：界面可操作后再注册 HealthKit observer、启动 anchored query、Watch 状态和可选 Mac 发现；每个模块独立更新。

同时执行：

- 将队列统计合并为一次后台读取，不在首帧做五次同步查询。
- 健康首页读取每日聚合快照，不在启动时逐条解码数千个原始样本。
- 去掉启动期间重复的训练智能计算，数据变更后合并刷新一次。
- 为 `process_start → first_frame → cached_dashboard → health_refresh_complete` 增加性能标记。
- 退出门槛：真机连续 10 次冷启动无白屏、无不可点击状态；缓存首页 p95 小于 1 秒，具体预算以首轮真机基线再收紧。

2026-09-04 Round 1 已落地：HealthKit 批次改为导入完成后统一触发派生历史刷新，后台投递注册从前台刷新路径拆开；单元测试已全绿。下一步仍需在真机上用 Instruments/MetricKit 记录 `first_frame`、`cached_dashboard`、`health_refresh_complete`，再决定是否引入轻量 `DashboardSnapshot` 日聚合缓存。

## 8. 视觉原则

- 保留现有荧黄色，只用于品牌、当前选中状态和唯一主操作。
- 健康指标使用稳定的语义色；颜色不单独表达好坏。
- 减少大卡片叠放，优先使用留白、标题层级、分组和行分隔。
- 首页只突出一个结论和一个行动；完整指标进入健康页。
- 图表默认显示真实点和轻量趋势，支持触摸/拖动、日期锁定、基线与缺失数据标记。
- 当前趋势图已经具备横向选点与数值回读能力；本轮重点是增强可发现性、触感、日期锁定、个人基线和缺失数据表达，不重复实现已有交互。
- 不照搬 StressWatch 的主题、插画或文案；借鉴的是首屏速度、信息层级、端侧处理和低摩擦交互标准。

## 9. 实施门槛

在修改 SwiftUI 导航和首页之前，先确认一套视觉方向。确认后按以下顺序实现：

1. 新建设置根页面，把现有 DataView 中的权限、Watch、同步、隐私、外观与诊断能力拆入对应分组。
2. 将底部导航固定为 `今日 / 健康 / 训练 / 趋势 / 设置`，训练保持中央位置；移除普通页面右上角的全局设置入口。
3. 建立轻量 DashboardSnapshot 与三阶段启动流程。
4. 重构今日首页，再补健康领域详情。
5. 真机验证五项导航、冷启动、返回前台、部分权限、无网络、VoiceOver 和超大动态字体。
