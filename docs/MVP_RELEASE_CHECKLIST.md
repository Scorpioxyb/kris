# Kris MVP 发布检查清单

执行状态与证据单独维护在 [商用执行计划](COMMERCIAL_EXECUTION_PLAN.md)；本文件保留为发布时逐项签字的不可跳过门禁。`代码存在`不等于`已验收`，涉及 HealthKit、Watch、离线、同步和可访问性的条目必须有目标真机证据。

## 核心闭环

- [x] HealthKit 首次回溯 42 天，12 类指标逐项显示进度。
- [ ] 用户拒绝任意非核心权限后 App 仍可进入首页。
- [x] iPhone 与 Python 准备度黄金样本完全一致。
- [ ] 当前计划成功发布到手机，训练开始后修订锁定。
- [ ] iPhone 能完成重量、次数、组次与末组感受记录。
- [ ] Watch 能启动 workout、采集心率并离线记录事件。
- [ ] App 被强制退出后训练草稿能够恢复。
- [ ] 同一会话重复上传不会在长期档案生成第二条记录。
- [ ] Mac 派生失败时手机队列不清除，并显示可行动原因。
- [ ] 归档成功后手机取得引用本次训练的新快照/下一计划。

## 数据正确性

- [x] 睡眠先聚合连续会话再归日，跨上午10点不被拆成午睡；同状态重叠区间按并集去重。
- [ ] 晨起体测必须为体重、体脂、去脂体重、BMI 同时间成套记录。
- [ ] HealthKit 覆盖完整时不与 SyncHealth 重复相加。
- [ ] HealthKit 覆盖不完整时，回退来源和覆盖状态清晰可见。
- [ ] 活动能量和静息能量经过覆盖检查，不按单日值直接“吃回”。
- [ ] 缺失主观反馈保持“未填写”，不解释为无症状或难度合适。
- [ ] 数据来源、时间、单位、规则版本和置信度可追溯。

## UX 与可访问性

- [ ] 首屏 3 秒内能回答：今天是否训练、主要限制、第一件事。
- [ ] 一组训练从查看到完成不超过一次主要点击。
- [ ] 所有核心触控目标至少 44×44pt。
- [ ] VoiceOver 可完成授权、开始训练、完成组、结束训练与同步。
- [ ] 默认/深色模式和辅助超大字体无横向溢出或关键内容遮挡。
- [ ] 空状态、部分权限、无计划、离线、证书错误、同步失败均有专门文案。（HealthKit 无数据/权限/签名能力/普通失败已完成，其余待验收）
- [ ] 训练中收到新计划不会替换当前计划。
- [ ] 所有红色/警告状态都给出下一步，不只显示错误代码。

## 性能与可靠性

- [x] 自动化单元和 UI 测试全部通过。
- [ ] Crash-free sessions 达到阶段 SLO。
- [ ] 缓存计划冷启动 p95 < 2 秒。
- [ ] 有网同步 p95 < 10 秒。
- [ ] 24 小时离线后恢复网络能自动补传且无重复。
- [ ] iPhone/Watch 时钟偏差和乱序事件不会破坏组次顺序。
- [ ] 生产构建包含正确 App Icon、版本、隐私清单和 entitlements。

## 隐私、安全与健康边界

- [ ] HealthKit 权限文案逐项说明用途，未请求当前不需要的数据。
- [ ] 只把真实完成的 workout 写入 HealthKit。
- [ ] 健康数据不用于广告、营销画像或无关数据挖掘。
- [ ] 设备令牌只存 Keychain，传输使用 TLS 和证书固定。
- [ ] 配对令牌一次性、短时有效，并可撤销设备。
- [ ] 提供数据导出、撤销授权和删除路径。
- [ ] 准备度和训练建议不使用诊断/治疗宣称。
- [ ] 异常症状门槛可以强制停止训练建议。
- [ ] 第三方 SDK 完成数据流清单和最小化审查。

## 商业发布

- [ ] 使用付费 Apple Developer Program 和 TestFlight 验证分发。
- [ ] App Store 审核提供可运行演示模式、样本计划和非显性功能说明。
- [ ] 隐私政策、支持 URL、联系方式、服务条款和健康免责声明可访问。
- [ ] StoreKit 2 支持购买、恢复购买、订阅管理和服务端通知。
- [ ] 免费功能不隐藏安全门槛或用户自己的历史数据。
- [ ] 订阅价值来自持续个性化与更新，而非故意制造数据焦虑。
- [ ] 发布前完成回滚、远程 kill switch、事故响应和客服流程演练。
