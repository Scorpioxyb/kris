# Kris V0.1.1 稳定化与本地闭环看板

> 建立日期：2026-09-06
> 原目标保留为训练模块验收：连续使用 7 天并形成可归因训练闭环。2026-09-06 起，产品总目标转为 [日常健康与专业训练](PRODUCT_ROADMAP_2026-09-06.md)，不再要求低频训练用户一周完成 3 次训练。

## 产品定位调整（2026-09-06）

产品从“力量训练计划执行器”调整为“个人健康与训练中枢”。日常健康、恢复、轻活动与身体趋势是大众用户主流程；力量训练计划、动作实绩、同器械进阶和 Watch 执行是差异化专业模块。训练频率降低不等于产品失去使用价值，也不强迫用户每天进入训练。

下一阶段优先级：

1. 今日页前置健康数据和活动入口，不把无计划或低频训练当作失败，不按次数推断恢复需求。
2. 健康页增强睡眠、恢复、活动、身体组成的可读性和数据来源。
3. 训练模块支持用户自行计划，低频训练者也能保留进阶证据。
4. 趋势页增加周/月层面的健康变化，不以训练次数作为唯一价值指标。
5. 设置保留本地数据、权限和隐私控制；不引入强制账号、Mac 配对或云依赖。

## 当前结论

代码、模拟器和正式构建已经具备继续开发条件；真机 Watch、锁屏恢复、离线补传、同步归档和性能 p95 仍需要设备证据。V0.1.1 只处理稳定性、执行摩擦和本地计划闭环，不扩展聊天、饮食、动作识别、社区或订阅。

## 开发顺序

1. **性能与启动**：使用 `AppPerformanceTrace` 记录 `process_start`、`first_frame`、`cached_dashboard`、`health_cache_restored` 和 `health_refresh_complete`；真机建立基线后再决定是否引入 `DashboardSnapshot`。
2. **训练执行**：优先保证一组记录的路径短、训练中不被健康刷新打断、锁屏后状态完整恢复；复杂编辑保持在手机训练页。
3. **跨端状态**：统一 iPhone、Watch、Live Activity 的 workout 生命周期和计时来源；验证断线、乱序、重复和强杀恢复。
4. **本地计划引擎**：先实现确定性最小规则集，再支持用户创建、复制、编辑、发布和回退；计划变化必须带证据和规则版本。
5. **Dogfood**：记录真实使用指标，再决定 Alpha 需要修复的 P0/P1。

## 本轮已落地

- 首屏性能阶段标记已加入原生 App，只写本地系统日志，不发送健康数据。
- 模拟器 Preview 构建通过。
- 现有未提交现场全部保留。
- 本地计划门控基础已实现：安全信号优先；缺计划、缺数据、过期/低置信度数据分别返回待补计划或待评估；不会从准备度自动授权加重。
- 计划门控回归测试已加入，覆盖安全优先、缺数据、刷新时效、置信度、症状缺失和加重隔离。
- 候选计划闭环基础已加入：本地保存候选、待确认状态、显式发布/拒绝和结构校验；未确认候选不会替换当前计划。
- 产品定位调整的首页切片已加入：健康与活动前置，非训练日不显示空训练警告，过期计划留在训练入口，核心指标可点击进入健康详情。

## 不得提前进入的工作

- 不以新增图表、AI 聊天、饮食记录或动作识别掩盖训练闭环缺口。
- 不在真机证据缺失时把 Watch、同步、性能或数据覆盖标记为 verified。
- 不把个人 Mac/Obsidian 作为公开商用后端；它们只服务于开发期迁移和归档。
