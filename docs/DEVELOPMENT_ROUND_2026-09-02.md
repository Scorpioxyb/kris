# Kris 新一轮开发计划

> 制定日期：2026-09-02
> 版本目标：V0.1.1 → V0.1.3 私人真机版本
> 产品方向：确定性算法优先，用户可编辑，AI 不进入核心运行链路。

## 1. 已确认的产品决策

1. 训练计划优先由可测试、可解释、可版本化的算法生成；AI 以后只做自然语言录入、解释和候选建议，不直接绕过规则修改训练负荷。
2. 用户可以从空白、模板或历史计划创建自己的训练计划。个人阶段由外部教练生成的计划也只作为一种通用导入来源，进入 App 后使用同一套编辑、校验、修订和执行流程。
3. Apple 健康原始数据、恢复分析、训练负荷、动作进阶和图表默认在 iPhone 本地运行；Mac/服务端不作为打开 App 和查看数据的前置条件。
4. 训练执行必须与 HealthKit workout 状态一致，支持准备、开始、暂停、继续、停止、结束、崩溃恢复和跨端镜像。
5. 灵动岛、锁屏实时活动和组件计时使用系统状态驱动，不另建一套会与 workout 漂移的计时器。
6. GitHub 首次上传使用私人仓库；运行时、README、提交信息和贡献者信息只保留项目自身内容，个人健康数据与本地密钥永不入库。
7. UI 保留荧黄色品牌语言，但只用于品牌与主操作；健康曲线使用语义色，并提供触摸选择、具体数值、基线和数据质量解释。

## 2. 本轮架构调整

### 2.1 确定性计划引擎

新增纯函数 `PlanningEngineV1`，输入为：

- 用户目标、可训练日、可用时长和器械。
- 当前训练模板与微周期位置。
- 同器械最新重量×次数、完成率与末组感受。
- 7/42 日负荷、最近训练间隔、恢复状态和数据置信度。
- 腰骶、肩肘腕、膝髋等明确症状与安全限制。

输出为：

- 当天训练类型与预计时长。
- 热身、主体、收操三个区块。
- 每个动作的重量、组次、次数/时长、休息和替代动作。
- 每一项调整的规则编号、证据和回退条件。
- `proposed / active / locked / completed / cancelled / superseded` 状态。

规则必须使用黄金样本测试。相同输入必须得到相同计划；数据缺失只能降低置信度或保持现有负荷，不能随机生成进阶。

### 2.2 用户自建计划

新增计划库与编辑器：

- 从空白计划、模板、历史计划复制。
- 拖动调整动作顺序。
- 编辑器械变体、重量、组数、次数、休息和替代动作。
- 支持重复、按侧、按时长和按距离处方。
- 保存草稿、发布修订、恢复上一个修订。
- 开始训练后锁定修订；编辑只影响下一次训练。

外部生成计划统一标记为 `imported`，仓库与 App 不绑定某个 AI 服务名称。

### 2.3 TrainingPlan.v2

现有 V1 不能正确表达热身、收操、时间型动作和计划来源。本轮设计 V2：

- `sections`: `warmup / main / cooldown`。
- `prescription.kind`: `repetitions / duration / distance`。
- `laterality`: `bilateral / left_right / alternating`。
- `weight_mode`: `total / added / per_side / bodyweight`。
- `origin`: `user / algorithm / imported / template`。
- `workout_activity_type` 与室内/户外。
- 规则证据、修订状态和被替代关系。

V1 继续只读兼容；迁移不得改变已完成训练。

## 3. 原生训练与 Apple Watch

### 3.1 WorkoutCoordinator 状态机

建立单一状态机：

`idle → preparing → running ↔ paused → stopped → finalizing → completed`

要求：

- `HKWorkoutSessionDelegate` 是 workout 状态权威来源。
- 暂停时间不计入有效训练时长；总经过时间另行保留。
- Watch、iPhone、锁屏和灵动岛显示同一状态。
- 暂停、继续、停止事件均带唯一 ID，并持久化、去重、可乱序重放。
- 强杀后使用系统恢复 API 重连活动 workout，再恢复当前动作与已完成组次。
- 系统 workout 完成后只写入一条 HealthKit 记录。

### 3.2 与 Apple 健身的边界

推荐执行路径：从 Kris Watch App 开始训练，由 App 创建标准 HealthKit workout；完成后仍进入 Apple 健身/健康，运动类型、心率、时长与能量保持原生记录。

兼容路径：如果用户从 Apple 自带“体能训练”开始，Kris 不尝试同时创建第二个主 workout。训练结束后读取 HealthKit 记录，按时间重叠和运动类型关联到训练会话，并明确标记“系统训练后关联”。该路径不承诺实时心率、暂停状态或后台组次界面。

系统边界：watchOS 不允许两个 App 同时拥有主 workout；Kris 不能接管已经由 Apple“体能训练”启动的会话。因此“完整实时联动”和“继续从系统体能训练入口启动”不能同时承诺。产品默认采用前者，并把运动结果写回 Apple 健身；后者只作为兼容模式。

研发验证：评估 WorkoutKit 的 `openInWorkoutApp()` 与训练计划日程能力是否适合力量训练；未通过真机验证前不写入正式产品承诺。

### 3.3 灵动岛与锁屏实时活动

增加 ActivityKit/Widget Extension：

- 紧凑态：当前动作或组间倒计时。
- 展开态：动作、当前组/总组、目标重量×次数、有效训练时长。
- 暂停态：明确显示“已暂停”，计时冻结。
- 休息态：倒计时、跳过、增加 30 秒。
- 结束态：完成组数、时长和保存状态，短暂展示后关闭。

第一版只做训练与休息，不加入准备度小组件；防止本轮范围膨胀。

## 4. 健康数据体验升级

### 4.1 信息架构候选

推荐将日常入口调整为：

1. `今天`：状态、限制因素、今日行动和当前计划。
2. `健康`：恢复、睡眠、活动、身体成分、心肺能力。
3. `训练`：计划库、当前训练、历史与动作进阶。
4. `趋势`：跨指标关联、7/28/42/90 日变化。
5. `设置`：健康权限、Watch、同步、隐私、外观、辅助功能和诊断。

底部固定顺序为 `今日 / 健康 / 训练 / 趋势 / 设置`。HealthKit 权限、同步队列、导出和诊断从原 `数据`页重构进第五个 `设置`入口，普通页面右上角不再重复放全局设置按钮。该调整先完成真机尺寸视觉方案，再改导航代码。

2026-09-02 用户再次确认：`数据`不再作为一级入口；首页从训练状态页升级为完整的今日健康与行动入口；设置保留在底部，采用五 Tab。详细结构和性能方案见 [首页与导航 VNext](HOME_NAVIGATION_VNEXT.md)。

### 4.2 健康领域详情

- 恢复：准备度、HRV、静息心率、睡眠和近期训练负荷。
- 睡眠：总时长、阶段、入睡/醒来时间、规律性和睡眠负债；缺失阶段不伪造。
- 活动：步数、活动能量、静息能量、锻炼分钟和 workout 分布。
- 身体成分：体重、体脂、去脂体重、BMI 与晨起成套测量质量。
- 心肺：VO₂ max、训练心率、步行心率等有连续覆盖的指标。
- 每个详情必须显示来源、更新时间、个人基线、置信度和影响。

### 4.3 数据更新与首屏体验

- 首次授权后直接由 iPhone 读取 HealthKit；SyncHealth 只保留为 Mac 历史兼容来源，不是手机 App 的依赖。
- App 启动先显示 SwiftData 中上次可信快照与当前计划，再异步执行 anchored query；不得用空白页或全屏加载等待 HealthKit。
- 使用 `HKObserverQuery`、后台投递和回到前台补查形成事件驱动更新，不做分钟级或小时级轮询。
- “实时”定义为系统允许时尽快更新，而不是承诺每个 HealthKit 指标秒级送达；界面必须显示采样时间、读取时间和是否仍在刷新。
- 单项读取失败不阻塞其他指标，旧可信值保留并标记新鲜度；不得把缺失值显示为正常。

### 4.4 交互图表标准

- 默认显示真实点位与轻量面积层，不使用荧黄色编码健康数据。
- 采用不会制造虚假峰值的平滑方式；体重同时显示原始点和 7 日趋势。
- 支持点击/拖动选择、十字线、数值浮层、触感反馈和日期锁定。
- 支持 7/28/42/90 日切换，并记住用户上次范围。
- 支持基线、目标区间、权限缺口和不完整日的视觉标记。
- VoiceOver 提供图表摘要和逐点浏览，不能只依赖颜色表达好坏。

参考项目仅作为交互和代码组织基准，采用前先复核许可证和适用性：

- Apple `sample-food-truck`：SwiftUI 多平台结构与系统组件使用。
- `SleepChartKit`：Apple 风格睡眠阶段图。
- `Steps`：HealthKit + SwiftUI 数据流。
- `atria`：本地优先恢复/健康信息架构。
- `iOS16-Live-Activities`：ActivityKit 与灵动岛实现方式。

不得直接照搬视觉资产、产品文案或未经验证的健康算法。

## 5. GitHub 私人仓库发布门

当前仓库没有首个提交，禁止直接上传。发布前依次完成：

1. 扩充 `.gitignore`：排除 `companion/.state/`、证书、密钥、SQLite、DerivedData、输出截图、个人计划和本地配置。
2. 把绝对个人路径改为环境配置或未跟踪的 `Local.xcconfig` / `.env.local`。
3. 将内部教练规则、个人 Obsidian 数据工具和 App 产品源码分层；产品仓库不包含个人健康资料。
4. README 与产品文档只描述产品能力、架构和贡献者信息。
5. 使用当前 GitHub 用户自己的 Git 身份创建初始提交，不添加 `Co-authored-by` 或自动生成工具署名。
6. 执行密钥、个人路径、大文件、证书和健康数据扫描。
7. 增加 GitHub Actions：Python 测试、Swift 编译/单元测试、契约校验和秘密扫描。
8. 经本地净化清单通过后，再创建私人仓库并推送。

建议仓库名：`KrisCoach`。在用户明确确认仓库名之前不创建远端。

## 6. 执行顺序

### V0.1.1 — 基础与契约

- Git 安全基线与源码模块化入口。
- 缓存优先首屏、后台 HealthKit 增量更新和数据新鲜度状态前置完成。
- `TrainingPlan.v2`、计划状态机和 V1 兼容迁移。
- `PlanningEngineV1` 最小规则集与黄金测试。

- 修复计划双重权威与发布前校验。

退出门槛：冷启动不等待 HealthKit 才能查看上次可信状态和计划；用户计划与算法计划都能经过同一流程执行；同一日期不会静默激活两个计划；无个人数据或密钥进入 Git 暂存区。

### V0.1.2 — 原生 workout 与实时活动

- Watch/iPhone workout 状态机。
- 暂停、继续、停止、恢复与有效时长。
- workout mirroring 和强杀恢复。
- ActivityKit 锁屏与灵动岛。
- Apple 自带 Workout 事后关联实验。

退出门槛：真机完成开始→暂停→继续→锁屏→停止→保存；Watch、iPhone、灵动岛和 HealthKit 状态一致且只生成一条 workout。

### V0.1.3 — 健康与图表体验

- 健康详情信息架构。
- 睡眠、恢复、活动、身体成分、心肺五类详情。
- 交互曲线、范围切换、基线和数据质量标记。
- 缓存首屏性能、加载占位和刷新过渡。
- 深浅色、动态字体、VoiceOver 与真机视觉验收。

退出门槛：缓存首屏 p95 < 1 秒；任一健康指标三次操作内可追溯来源；所有核心曲线可点击读取具体点；缺失数据不会显示为正常。

## 7. 本轮暂不做

- App 内聊天和在线 AI 自动处方。
- 社区、排行榜、动作自动识别和摄像头纠姿。
- 完整营养数据库与拍照识餐。
- 公有云多租户、订阅和正式 App Store 发布。
- Android。

## 8. 每轮沟通与验收

每个版本开始前固定给出：问题、范围、不会做的内容、真机验收动作。每完成一个可见功能，先提供模拟器或真机证据，由用户确认方向后再继续下一批。任何涉及健康算法、训练加量、导航结构或品牌语言的变化都不得静默修改。

## 9. 2026-09-02 当前界面审计结论

本轮使用 iPhone 17 Pro Max 尺寸的当前原生预览逐页核对，结论如下：

1. `今天`：核心行动入口清楚，荧黄色品牌按钮有效；但准备度、限制、计划和指标卡仍偏“结果堆叠”，健康证据的更新时间与可追溯入口不够突出。
2. `训练`：重量和次数可直接调整，单组完成路径已经可用；但缺少训练级暂停、继续、停止以及 workout 状态，尚不能承担完整原生训练入口。
3. `趋势`：范围和指标切换清楚，当前蓝色曲线比荧黄色更适合健康数据；代码已支持横向选点和数值回读，但交互提示不明显，仍缺少持久日期锁定、个人基线和缺失数据语义。
4. `数据`：权限、Watch、Mac 和离线队列状态表达清楚；但“数据”不是用户任务，应拆为健康详情和第五个底部 `设置`入口。

因此 UI 开发顺序固定为：先补训练状态与健康信息结构，再做视觉精修；保留现有荧黄色品牌语言，不另起一套主题。

## 15. 趋势图 Demo（2026-09-04）

设计工作台现提供四套可直接比较的趋势图样式：点线、面积、柱线、极简；体重、体脂和恢复指标共用同一组 7 天演示数据，点按每日点位会回显日期、数值和单位。训练负荷另提供柱状与短期/长期双轨两套视图，双轨使用实线/虚线和图例区分短期、长期负荷。

本 Demo 只用于确认信息层级与视觉方向，不把演示数据写入 HealthKit、SwiftData 或 Obsidian。用户选定方向后，再将组件规则回写原生 SwiftUI，并补充 7/28/42/90 日范围、基线和数据缺口标记。

这六项通过后再进入 workout 状态机与灵动岛，避免在即将迁移的数据模型上并行堆 UI。

## 11. 2026-09-03 Build 6 进展

本批保留五栏原生玻璃导航和内容延伸到底栏后方的布局，不再增加重复底部留白。

已完成第一段 workout 生命周期闭环：

- Watch 以 `HKWorkoutSessionDelegate` 回调作为开始、暂停、继续、停止和结束的状态权威；启动失败不再显示为训练中。
- iPhone 与 Watch 均显示有效训练时长和总经过时长；暂停期间有效时长冻结。
- 生命周期快照带单调序号并随事件持久化，重复或迟到事件不能把较新的暂停/完成状态回滚。
