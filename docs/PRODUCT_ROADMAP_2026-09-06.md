# Kris：日常健康与专业训练

决策日期：2026-09-06。后续产品排期以本文件为准；不覆盖历史开发记录。

2026-09-11 补充：国内同类产品功能对照、当前体验审计与阶段路线见 [Kris 国内同类产品与体验审计](COMPETITIVE_PRODUCT_AUDIT_2026-09-11.md)。该审计收敛了首页状态、趋势个人基线和专业训练的关系，不改变本文件的“日常健康 + 专业训练”定位。

## 定位与人群

面向有 Apple 健康数据、希望理解日常状态的学生和忙碌上班族；健身频率可以是零次、偶尔或规律训练。首批仍聚焦 iPhone 用户，不以“适合所有人”替代明确场景。

核心价值：不用每天去健身房，也能看懂睡眠、活动与身体变化；需要训练时，又能记录实际组次、现场换器械、使用 Watch 和逐步进阶。健康数据默认本机处理，训练是专业优势而非使用门槛。

不因减少健身安排降低产品评价，不用训练打卡连续天数制造压力。用户本次反馈“基本没有卡顿”属于主观体验改善证据，不等于已测得真机性能 p95。

## 信息结构

保留当前五项系统 Tab、品牌标识、荧黄点缀和原生材质，不重新设计一套视觉皮肤。

| 页面 | 核心任务 | 本轮边界 |
|---|---|---|
| 今日 | 快速查看健康与活动，继续正在进行的训练 | 健康四格和活动优先；没有计划不告警；旧计划不显示为今天 |
| 健康 | 查看睡眠、恢复、活动、体成分、心肺详情 | 原有恢复模型仍是训练准备度，不能直接改名成通用健康分或实时心理压力 |
| 训练 | 安排计划、记录、回顾表现 | 保留独立入口；低频训练不重置个人动作历史 |
| 趋势 | 看数周的变化和数据覆盖 | 下一版强化周总结，不以训练次数代替健康状态 |
| 设置 | 权限、隐私、设备与偏好 | 不强制 Mac 配对、云账号或健康数据上传 |

首页不根据训练次数生成“该休息”或“可以训练”。缺失记录不等于缺少活动；四次散步也不能等同四次高负荷力量训练。安全异常优先于训练继续入口。

## MVP 验收

一个不去健身房的用户也能完成：授权或跳过授权 -> 浏览已有数据 -> 打开睡眠/活动/身体详情 -> 查看一周变化。部分授权、数据过期和离线时，缺失状态可见，页面仍可操作。

一个偶尔训练的用户可以通过训练 Tab 使用原有执行流程；首页仅显示当天计划或正在进行的会话。过期计划保留在训练中供查看，不静默改日期、补做或记录完成。

不增加自动建议通知、轮询、云端聊天、饮食数据库、社交、订阅或疾病诊断。短时活动方案需要独立设计，不能以一行通用文案宣称已具备个性化运动处方。

## 度量与技术约束

- 日常价值：能否找到当天睡眠/活动信息、能否解释相对基线变化；任务是否完成不由健身次数决定。
- 可靠性：缺失数据误显示正常的案例数、训练保存失败、重复会话、跨日旧计划误展示。
- 性能：真机冷启动、前台恢复与组次点击延迟；同步时能操作。现有标记只是观测点，不是已测 p95。
- 留存：先做本地使用日记与明确同意的小范围反馈，不默认采集远程行为分析。
- HealthKit 保持 observer/anchored 增量更新，不承诺系统无法保证的秒级后台同步，不加定时轮询。

## 当前债务与状态

- 健康首页已进入第二切片：日常“身体状态”替代首页训练处方表达，状态分与证据同层展示，重复数据缺口收拢为紧凑入口；不声称已有完整大众化健康算法。
- 单指标趋势已支持触摸回读，并为睡眠、HRV、静息心率显示可用的个人基线；7/42 日负荷已使用不同线型，仍需小屏、深色和超大字体视觉回归。
- 候选计划 API 虽已存在，但恢复读取、保存错误传播、确认状态严谨性和候选/正式计划原子发布尚未完整验收；旧的单路径测试通过不等于产品闭环完成。此模块接 UI 前必须补齐。
- `localPlanDecision` 仍缺当日主动症状输入；不能据此自动出版处方。
- 原有健康页中“恢复与压力”仍需区分训练准备度和心理压力；不能因扩大定位就复用同一分数解释所有身体状态。
- 本轮不安装或覆盖真机；保留当前已改善的在用版本，模拟器验证后再安排安装。
